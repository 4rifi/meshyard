## Scope and implementation

Implemented pure domain types; separate closed `wire::v1` schema and conversions; exact raw
Ed25519 signing/verification through Signer/Verifier; BLAKE3 raw-genesis identity; staged
receive validation; default sharing filter; deterministic two-phase membership/ordinary fold;
UI-domain binding generation; SQLite migrations and dedicated DB-thread handle; device identity
backends and exclusive process locking.

The store persists the original outer envelopes and signed payloads, verifies every remote
signature independently, compares signed bytes before field validation, preserves the first
payload on equivocation, flags violations, holds gaps, promotes contiguous pending sequences
transactionally, isolates workspaces and bounds requests/pending buffers. Invalid field events
are never persisted; later sequences leave an intentional gap. Async callers use a bounded
Tokio channel, with `open_async` available for initial synchronous filesystem/migration work.
Own sequence allocation, signing and insertion are serialized and transactional. Default own
append records the observed membership epoch and timestamp; explicit context/policy is also
available. Queries cap 256 events / 256 KiB; pending caps 1024 events / 1 MiB per author/workspace.

Identity uses explicit backends. The production Keychain record is service
`computer.meshyard.device`, account `device`; absence is distinct from locked/unavailable or
malformed records, and only absence permits key generation. Native create-only insertion avoids
keyring's upsert behavior and race-based replacement. File identity uses a private parent,
0600 no-follow files, rejects symlinks/hardlinks/unsafe permissions, fsyncs a new staging inode
and atomically links it into place without overwriting unknown files. Secret Debug/errors are
redacted; identity load/generation buffers zeroize; no secret is bound into SQLite or exported.

Fold seeds the genesis owner at epoch zero; processes only owner membership in sequence order;
then ordinary events for all final members, including the owner. Agents are keyed by
(author, local_id). Unknown membership is bounded and never speculative; late owner membership
makes prior accepted ordinary events project. Cross-author interleaving and timestamps do not
change the result.

## Design choices, limits and deviations

Architecture §11 records initial nested wire enum vocabulary, Member-only wire role, raw ALPN
frame type allowlists, receive-stage wrapper, conservative fold holding accounting, explicit
policy provenance and retained scaffold version helpers. These are initial reviewable choices,
not new claims of architect approval. The six normative bodies/field orders/domain separators
and ADR-009/010 are preserved; no protocol text was weakened.

SQLite's supported sequence range is **1..=i64::MAX**. Values above it reject with a typed
SequenceRange result; zero rejects; own allocation and promotion use checked addition. Cursor
conversion also rejects overflow. Tests cover i64::MAX, i64::MAX+1 and u64::MAX. Epoch addition
is checked. Postcard-compatible redundant varints are authenticated/stored as received and
compare differently for equivocation; verification/dedupe do not reserialize.

Sharing defaults remove task free text, preserve legitimate agent labels and structured enums,
and expose no raw prompt/command/path field. Source provenance is a caller/adapter contract:
arbitrary user label text cannot be proven secret-free by content inspection. Explicit task
opt-in is deliberate; T-007 must enforce hook allowlist extraction. This task introduces no
runtime logging and does not claim a future application-wide redaction layer already exists.

UI exports are domain-only. There is no Tauri bridge/serialization transport in T-002; T-009
will connect the bindings. Identity/permission guarantees and manual coverage here concern
macOS/Unix, not the later M5 platforms. Pairing tables reserve state/transcript columns; pairing
logic remains T-005. Sender-only connection authorization and re-request behavior remain T-006;
store signature verification never assumes transport authentication or third-party serving.
