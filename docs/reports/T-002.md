## Scope and implementation

Implemented pure domain types; separate closed `wire::v1` schema and conversions; exact raw
Ed25519 signing/verification through Signer/Verifier; BLAKE3 raw-genesis identity; staged
receive validation; default sharing filter; deterministic two-phase membership/ordinary fold;
UI-domain binding generation; SQLite migrations and dedicated DB-thread handle; device identity
backends and exclusive process locking.

The store persists the original outer envelopes and signed payloads, verifies every remote
signature independently, compares signed bytes before field validation, preserves the first
payload on equivocation, flags violations, holds gaps, promotes contiguous pending sequences
transactionally, isolates workspaces and bounds requests/pending buffers. Invalid field events
are never persisted; later sequences leave an intentional gap. Async callers use a bounded
Tokio channel, with `open_async` available for initial synchronous filesystem/migration work.
Own sequence allocation, signing and insertion are serialized and transactional. Default own
append records the observed membership epoch and timestamp; explicit context/policy is also
available. Queries cap 256 events / 256 KiB; pending caps 1024 events / 1 MiB per author/workspace.

Identity uses explicit backends. The production Keychain record is service
`computer.meshyard.device`, account `device`; absence is distinct from locked/unavailable or
malformed records, and only absence permits key generation. Native create-only insertion avoids
keyring's upsert behavior and race-based replacement. File identity uses a private parent,
0600 no-follow files, rejects symlinks/hardlinks/unsafe permissions, fsyncs a new staging inode
and atomically links it into place without overwriting unknown files. Secret Debug/errors are
redacted; identity load/generation buffers zeroize; no secret is bound into SQLite or exported.

Fold seeds the genesis owner at epoch zero; processes only owner membership in sequence order;
then ordinary events for all final members, including the owner. Agents are keyed by
(author, local_id). Unknown membership is bounded and never speculative; late owner membership
makes prior accepted ordinary events project. Cross-author interleaving and timestamps do not
change the result.

## Design choices, limits and deviations

Architecture §11 records initial nested wire enum vocabulary, Member-only wire role, raw ALPN
frame type allowlists, receive-stage wrapper, conservative fold holding accounting, explicit
policy provenance and retained scaffold version helpers. These are initial reviewable choices,
not new claims of architect approval. The six normative bodies/field orders/domain separators
and ADR-009/010 are preserved; no protocol text was weakened.

SQLite's supported sequence range is **1..=i64::MAX**. Values above it reject with a typed
SequenceRange result; zero rejects; own allocation and promotion use checked addition. Cursor
conversion also rejects overflow. Tests cover i64::MAX, i64::MAX+1 and u64::MAX. Epoch addition
is checked. Postcard-compatible redundant varints are authenticated/stored as received and
compare differently for equivocation; verification/dedupe do not reserialize.

Sharing defaults remove task free text, preserve legitimate agent labels and structured enums,
and expose no raw prompt/command/path field. Source provenance is a caller/adapter contract:
arbitrary user label text cannot be proven secret-free by content inspection. Explicit task
opt-in is deliberate; T-007 must enforce hook allowlist extraction. This task introduces no
runtime logging and does not claim a future application-wide redaction layer already exists.

UI exports are domain-only. There is no Tauri bridge/serialization transport in T-002; T-009
will connect the bindings. Identity/permission guarantees and manual coverage here concern
macOS/Unix, not the later M5 platforms. Pairing tables reserve state/transcript columns; pairing
logic remains T-005. Sender-only connection authorization and re-request behavior remain T-006;
store signature verification never assumes transport authentication or third-party serving.

### Findings and narrow fixes

1. **Directory trust / TOCTOU (confirmed source finding).** The previous metadata checks
   followed by mutable-path operations and leaf-only O_NOFOLLOW did not establish trust in
   ancestors. This run does **not** reproduce the auditor's claimed secret read: POSIX directory
   ownership does not grant read access to another UID's 0600 file. Substitution can redirect
   operations, deny service, and interact with ACL/inherited access. Tests cover those concrete
   trust boundaries; no second-user key theft is claimed.

   Chosen alternative permitted by the fix request: reject ancestors mutable by other OS users,
   then exclusively use the validated canonical spelling. Root-down checks require root/current
   effective UID ownership and no group/other write, except root-owned sticky temp parents;
   the private leaf must be current-UID/0700. rustix provides the actual effective UID through
   a safe API. macOS ACL reads use exacl; any nonempty allow entry (including inherited and
   benign current-user grants) fails closed, while deny-only ACLs remain acceptable. Linux
   POSIX ACL access grants are constrained by the group-class mode mask; this run tests macOS,
   not Linux. Unsupported platforms fail closed. Trusted root/admin and malicious same-UID
   processes, including same-UID path/mount changes after validation, are outside this policy.

   Identity load/create, staging write/link/removal/fsync, process-lock creation and SQLite
   worker open all use the canonical directory. File validation checks effective UID, single
   link, regular inode, 0600 and ACL before writing staging secrets. SQLite main/sidecar aliases
   reject before use, safely owned old database files are tightened to 0600, and the connection
   sets OPEN_NOFOLLOW. No custom VFS, directory-FD filesystem spelling, unsafe Rust or shell
   permission probes were introduced.

   Deterministic tests: unsafe writable ancestors reject before any key/lock/database write or
   missing-leaf mkdir; numeric foreign-owner policy fixtures use the actual effective UID with
   no chown/admin requirement; a same-UID test substitutes an ancestor symlink exactly between
   canonical validation and identity publication/cleanup or lock/DB open, proving the alternate
   destination stays empty. This is a controlled path-substitution regression, not an actual
   cross-UID exploit. Canonical `/tmp` beneath the root-owned sticky parent remains usable.
   Actual macOS extended/inherited ACL fixtures reject despite 0700. Main SQLite and all three
   sidecar names reject symlinks/hardlinks without changing unrelated bytes or permissions.

2. **Unbounded durable pending membership (confirmed source finding and reproduced shape).**
   Previously seq 1..1025 from a correctly signed unknown author went directly into `events`;
   only `pending_events` was quota-limited. The fix counts exact outer blob bytes and rows
   across **both** tables before storing any new never-confirmed-author event. The limit is
   1024 rows **or** 1 MiB per workspace/author, including unauthorized membership bodies.
   Duplicate/equivocation comparison remains before field validation, which remains before
   quota/persistence. Overflow transactionally discards that author's entire unconfirmed
   holding and rejects the triggering event. Its head disappears (zero); subsequent gaps
   remain gaps and T-006 can re-request the missing prefix. Old oversized holdings are also
   cleaned transactionally on reopen, after checking verified owner authority.

   Authority comes only from verified genesis plus a verified contiguous owner-log prefix;
   neither forged peer grants nor pending gapped owner grants exempt an author. Once validly
   confirmed, history remains established for retention even after reserved MemberRemoved;
   only its gap buffer is subject to the gap quota. No established contiguous history is
   deleted. Current projection membership still follows the full two-phase fold.

   Minimal return/storage choices pending review: Inserted still means contiguous durable
   storage (not authorization); Pending still means a sequence gap. No schema migration or
   extra copy is needed. A later valid owner grant makes the retained permissible ordinary
   events applicable in place; gap promotion does not double-count/copy them, and replay stays
   Duplicate. Own append commits an overflow drop but returns AppendRejected. Fold no longer
   indexes all unknown-author input before enforcing its bounded output holding.

   Tests cover unknown seq 1..1024, reopen/dedupe/equivocation, rejection at 1025, empty SQL
   holding/head reset, workspace isolation, later membership and resend, mixed contiguous/gap
   aggregate limits, late contiguous owner confirmation, exact preserved bytes, no double
   projection, established history beyond 1024 after MemberRemoved, gap overflow retaining
   that history, and injected SQL promotion failure with complete transaction rollback.
   A legacy database fixture inserts correctly signed seq 1..1025 directly via SQL to reproduce
   the old persistent shape; reopen discards only the unknown author's rows and keeps 1025
   confirmed rows. A separate synthetic SQL blob-size fixture checks exact 1 MiB acceptance
   and overflow across both tables: it is deliberately not a valid signed-wire exploit.
   Current small valid v1 bodies reach the count limit before the byte limit; the byte guard
   remains explicit. A third 256-case property checks unknown holding/overflow invariance
   under cross-author interleavings; the original properties and frozen goldens remain.
