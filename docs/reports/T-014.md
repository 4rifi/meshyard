## Result

The application now opens the real store and explicitly selected identity once, creates a
signed Strict genesis and owner `ProfileUpdated`, registers signed `AgentRegistered` events,
saves profile edits and reconstructs the screen from verified contiguous SQLite history.
No owner `MemberAdded` is emitted. One Tokio mutex serializes every full command including
its fresh projection, preventing competing creates and lost registrations. Secure OS randomness
supplies genesis nonces and agent IDs; timestamps are metadata only.

The setup form replaces the scaffold. The workspace displays its name, short IDs, saved mode,
members, agents, honest empty/peer states and a Pixi yard with tokens grouped by actual activity.
The accessible agent list receives the identical `AgentView[]`. Registration alone maps to
`state: null, provenance: null` (**No events yet**); the core fold's synthetic initial Idle is
never presented as an observation. There is no connection/success simulation, localStorage,
network endpoint, live activity, hook installation or identity-backend fallback.

A failed initial profile append reports `PartialCreate`, keeps the persisted workspace selected,
blocks a second create, remains explicit after reopen and offers profile repair. Other storage,
identity, busy-profile, permissions, migration, input and projection errors expose fixed typed
kinds and advice, without private paths, OS error text or secrets. A profile with more than one
workspace fails closed before identity loading; an identity absent from workspace membership is
also rejected. Only a truly missing key permits the existing `load_or_create` behavior.

## Deviations and gaps

- Installed Tauri requires `Result<AppStatus, AppError>` on borrowed async `State` handlers.
  They always resolve the semantic `AppStatus` produced by the common command functions;
  wire/DTO behavior remains Setup/Ready/Error. This is a small compiler-required adaptation.
- `AgentView.id` adds a stable full public author/local-agent key for React reconciliation;
  member views add `is_you`. No secrets or private paths/IPs are exported.
- A dedicated `PartialCreate` error and repair form make the non-atomic two-step create
  honest, including after restart. An error after a persisted mutation may require reloading
  saved state before retry; no rollback of a successful signed genesis is fabricated.
- Projection is deliberately bounded full replay, not an incremental projection. Large
  histories beyond the cap fail explicitly; large-yard performance is not measured.
- Native scenarios 1–4, actual WKWebView IPC/ACL/CSP, visual/narrow-window keyboard focus and
  screen-reader acceptance, native restart/second native process, successful Keychain roundtrip,
  live hook, P2P and owner acceptance are **NOT RUN / UNVERIFIED**. Headless command checks
  establish persistence/locking, not native proof. No browser or app was started.
- Original T-001 app/server on 1420 was left untouched and is not evidence for this code.
  No task was marked done and no cross-lane/status/spec/review file was edited.
- Structured implementation-error lessons are in USB `learning-notes.md`; no internal-disk
  learning log was written because this task explicitly requires all project logs on USB.
