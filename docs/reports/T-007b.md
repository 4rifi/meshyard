## Delivered source and callers

- `crates/meshyard-store/src/{lib,database,process_lock}.rs`: expose the canonical
  `Store::directory()` retained by the process lock and the existing ACL-aware `private_directory`
  without changing its permission logic. Add a third migration, leaving earlier migrations intact:
  local `agent_bindings(workspace, kind, agent_local_id)`, primary key `(workspace, kind)`.
- `Store::{bind_own_agent, bind_first_own_agent, agent_binding}` run on the existing database actor.
  Ownership/kind comes from verified registered agents and the application's signer, never a guessed
  agent ID. The first own registration of a kind auto-binds; later registrations do not change it.
  Existing registrations are not guessed or auto-bound during migration. Binding writes are local
  only and add no signed/synced event. Invalid/foreign registrations are rejected; stored bindings
  are revalidated when read.
- `app/src-tauri/src/ingest.rs`: one Tokio Unix listener, canonical `<data>/ingest/ingest.sock`,
  existing ACL-aware directory validation, 0600 socket, effective-UID peer credentials. Paths over
  103 bytes disable ingest; there is no alternative location. Startup only removes an existing
  socket owned by the effective UID. Other entries, including symlinks, are preserved and rejected.
  Cleanup checks the created socket's device/inode before unlinking.
- The listener has eight semaphore permits and a JoinSet capped at eight entries, including ready
  results. Excess connections close immediately. Readers use a fixed 1024-byte array and a 200 ms
  timeout, one newline-terminated envelope per connection. Parse/UID/read failures only increment
  internal counters. No input text is logged or retained. Counters saturate.
- One reviewed `meshyard-agents::StateMachine` per supported kind feeds signed `AgentState` appends
  under the existing AppCore mutex and default sharing policy. A five-second tick expires Finished
  to Idle. Changes compare state, provenance **and** tool against persisted state; repeated equal
  values do not append, including after pipeline restart. Hook task labels are always `None`.
- Per-agent appends are separated by at least 50 ms, measured from completed persistence. Excess
  changes coalesce to the latest tuple, with a 50 ms flush timer. Switching the explicit binding
  resets the kind's machine and drops any pending tuple for the previous agent. Rate bookkeeping
  retains one entry per used own registered agent, bounded by the existing projection limit.
- Actual lifecycle callers: `AppState::open_with_keys` starts ingest only after loading/verifying an
  existing workspace identity; `commands::create_workspace` starts it after durable creation and
  releasing the command lock; `AppCore::register` calls the first-own-agent binding API.
  `run().setup` attaches AppHandle; `RunEvent::Exit` joins listener/readers before normal teardown.
  `AppState::close` stops ingest before closing the store, with an abort/RAII fallback for drop.
  Existing workspaces still load identity only; no replacement identity or fallback was added.
- `AppCore::changed` emits `workspace-changed` with unit/null payload when AppHandle exists, after
  successful appends (creation/profile/registration/activity). No frontend listener or capability
  has been added. Internal ingest listening/unavailable/counter state is ready for a later DTO
