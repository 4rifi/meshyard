## Result and scope

checks, dependency-free inert hook, headless placeholder binary, and a Tauri 2 desktop shell.
`meshyard-net` re-exports iroh's `EndpointId` and does not construct an endpoint. Its iroh 1.3.0
source and `tls-ring` feature were inspected locally, but its compilation has **not finished**.

React 19 / strict TypeScript / Vite / PixiJS 8 render one rectangle with a persistent text
caption. Renderer ownership handles async init after unmount, repeated disposal, and failed
initialization; three Vitest tests cover these cases. No animation loop, external assets,
networking, IPC, plugins, SQLite schema, hook forwarding or other product features were added.
Production CSP denies connections, frames, workers, objects and forms; other assets are local.
Dev CSP allows loopback HMR and the Vite React-refresh inline script. The main capability has
an empty permissions array; no shell plugin is present. Native CSP behavior and actual Pixi
rendering in WKWebView remain unverified.

## Release hook latency

51 sequential `subprocess.run(['target/release/meshyard-hook'], input=b'', capture_output=True,
check=True)` invocations measured using `time.perf_counter_ns()` around process creation and
exit. All exited 0 with empty stdout/stderr. This is wall time including Python spawn overhead.
The first invocation immediately followed the release build, without a warm-up. OS page caches
were **not** flushed; this is a first observed process launch, not a controlled cold-cache test.

| Sample | Min (ms) | Median (ms) | Max (ms) |
|---|---|---|---|
| All 51, including first launch | 1.732375 | 2.141167 | 442.321500 |
| Following 50 launches | 1.732375 | 2.121854 | 11.121625 |

First launch: **442.321500 ms**. Therefore the requested <20 ms budget is **not met across all
measured launches**, despite all following launches being under 20 ms. The scaffold hook is an
empty std-only `main`; the cause of the first-launch overhead was not established. Do not claim
that removing this environmental overhead or future hook forwarding is already solved.

Dependency reasons:

- React/react-dom implement the minimal accessible shell; Pixi implements the required renderer.
- Tauri CLI/API and Rust tauri/tauri-build implement native packaging/shell; no IPC API calls.
  Rust tauri disables defaults and enables only wry/compression. No permission plugins.
- Vite/plugin-react handle local build/HMR. TypeScript and type declarations enforce strictness.
- ESLint/js, typescript-eslint, globals, React hooks/refresh plugins enforce typed React rules;
  Prettier handles formatting and Vitest tests renderer ownership without GPU or network.
- iroh 1.3.0 is required now by the task, default features off, tls-ring on, no endpoint created.
- tracing is used for a generic desktop failure event without sensitive fields. Core has no I/O.
- rusqlite, tokio, ts-rs, serde, serde_json, thiserror are **reserved workspace pins**, not direct
  scaffold crate dependencies. No schema/runtime/error derive/IPC feature is introduced just to
  activate them. Some are naturally present transitively through Tauri/iroh. The hook has zero
  dependencies, within the allowed std/serde subset.
