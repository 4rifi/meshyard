## Behavior and production callers

- `WorkspaceScreen.tsx` creates `createYard(host, onError)` once per available
  workspace identifier (`WorkspaceView.id_short`, the frozen DTO identifier),
  updates it when agent DTOs change, and destroys it on workspace replacement or
  unmount. The caption now describes movement on observed state changes. The
  existing statement that live status is not connected remains truthful.
- `playground/yard.ts` owns the persistent Pixi scene. UUID-keyed characters and
  HTML tags survive DTO reordering, label/provenance changes, other registrations
  and removals. Each live UUID retains its reservations at visited stations.
  New agents start at distinct Arrival slots, including when their first DTO
  already has a state. Removed agents release their characters and tags.
- `playground/yardData.ts`, called by the scene, accepts stable slot assignments.
  Two permanent slots per station and overflow plot avoid recentering existing
  agents when a second agent appears. Empty visited plots remain until scene
  destruction so removing or adding agents cannot shift another station/page or
  erase a corridor under a mid-walk character. Neutral plots retain actual future
  DTO labels without inventing workstation props.
- `playground/yardPath.ts`, called by `yard.ts`, derives slot/door/corridor edges
  from those actual plots in both 2- and 4-column layouts. Each row pair has one
  horizontal path; a narrow left lane joins row pairs and overflow pages. Side
  doors avoid routing through the existing workstation sprite. The shortest
  orthogonal route is split at intersections and the current integer position,
  so retargeting continues from that position.
- `walkRoute`/`step`, called by the scene ticker, use 48 logical pixels per second,
  speed up routes exceeding three seconds to a three-second route duration, and
  round displayed positions from cumulative route time rather than accumulating
  rounded per-frame displacement. Two poses reuse the existing character pixels
  with a one-pixel foot step (`sprites.ts`); there are no new colors or assets.
- Only moving characters run the private Pixi ticker. Arrival stops it; reduced
  motion snaps directly to the same DTO-derived target without an idle loop.
  Tags use the same integer position as the character. Existing nearest scaling,
  integer canvas/overlay origins, responsive scale 2 at 375, wrapping, full title
  strings and the complete unchanged accessible AgentList remain in use.
- Responsive **column changes snap existing identities to their new slots**,
  canceling the old-layout route. This is a geometry change, not an invented
  activity/state. A resize within the same column layout preserves the walk.
- Existing `sceneLifecycle.ts` remains the async initialization owner. Updates
  before initialization keep the latest DTOs; destroy-before-init never attaches
  a stale scene. Attach failure destroys initialized resources; repeated destroy
  is idempotent. Scene cleanup removes the ticker callback, media listener,
  ResizeObserver, canvas, tags, characters and reservations.
