## Required changes
1. **Install fails on a normal `~/.claude` (mode 0755).** Trigger: `hook_apply` → `apply()` calls
   `private_directory(~/.claude)`, which rejects any directory with `mode & 0o077 != 0`
   (`process_lock.rs:91`). Claude Code's `~/.claude` is commonly created with the default umask
   (0755), while `read()`/`plan()` accept it — so the owner sees a valid diff and then `Install`
   returns `UnsafePermissions`. Tests only use a 0700 parent (`hooks_tests.rs:7,24`). Smallest fix:
   for the **settings parent** use a dedicated check — existing real directory (no symlink), owned
   by euid, not group/other-writable (`mode & 0o022 == 0`), trusted ancestors — and never chmod or
   create the user's directory with a different mode (if it is missing, create it 0700 as today).
   Add tests: 0755 parent installs; 0775/0777 or foreign-owned parent rejected.
2. **A hook-config problem takes down the whole workspace view.** Trigger: `status_at` maps
   `Installer::view()` errors with `?` (`state.rs:199-203`), so a symlinked (dotfile-managed),
   hard-linked, group-writable, oversized or invalid `~/.claude/settings.json` turns every
   `app_status` into the full-screen error, although the workspace is fine. Smallest fix: in status,
   map a view error to `HookView { installed: false, binary_available }` (no new DTO field); the
   precise error is shown when the user opens the Connect panel (`hook_plan`). Add a test: invalid or
   symlinked settings → `Ready` with `installed = false`, and `hook_plan` returns the specific error.
