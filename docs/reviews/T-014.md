## Accepted
- **Signed persistence:** genesis via `sign_genesis` (owner = own device, Strict only, OS-random
  nonce), stored through `add_workspace`; owner seeded by genesis, first `ProfileUpdated` appended,
  no owner `MemberAdded`. Profile and agent registration are real `append_own` events.
- **Partial create is honest:** workspace id is held after a durable genesis, a second create is
  refused, the missing display name is surfaced as `PartialCreate` (also after reopen) with a
  repair form that uses the normal `update_profile` path. No rollback is faked.
- **One profile / one workspace / serialized mutations:** one `Store` + signer per process behind a
  `tokio::Mutex` held for each full command including the fresh projection; `MultipleWorkspaces`
  fails closed before identity load; an identity that is not a member → `IdentityMismatch`.
- **Bounded verified projection:** `workspace_state` verifies the genesis id, refuses > 100 000 rows
  with a bounded count before loading, re-verifies each contiguous signed row and runs the existing
  fold. Accepted as the documented bounded full replay (incremental projection is later work).
- **IPC/ACL:** exactly four commands in `generate_handler!`, the `AppManifest` and the capability
  (main window only, no plugins). DTOs are ts-rs generated; `client.ts` pairs command names and
  argument envelopes with a finite type map, no `any`; transport errors collapse to `IpcUnavailable`;
  inputs use `deny_unknown_fields`; views carry no paths, keys or IPs.
- **Truthful agent status:** `state` is shown only when an actual `AgentState` set provenance;
  registration alone renders "No events yet" without a badge. Yard and list use the same DTO and
  label function.
- **CSP:** `tauri.conf.json` CSP unchanged. The report's Tauri 2.12.4 source reading (custom-protocol
  fetch → `postMessage` fallback under `connect-src 'none'`) is plausible but is **source evidence,
  not native proof** — see N-14.
- **UI:** labelled inputs, fieldsets disabled while busy, focus moves to the `h1` on screen change
  and back to the label input after registering, visible `:focus-visible`, narrow-width media rule,
  reduced-motion rule, single static `app.render()` (no ticker), yard destroyed through the existing
  `sceneLifecycle`. Placeholder deleted.

## Required change
1. **A missing key on an existing workspace must not create a new identity.**
   `AppState::open_with_keys` calls `load_or_create(keys)` even when a workspace already exists.
   If the key is absent (deleted file identity, deleted Keychain item, or simply starting a
   file-key dev profile **without** `MESHYARD_KEY_STORE=file`), a brand-new device key is generated
   and **persisted** (in the latter case into the production Keychain record
   `computer.meshyard.device`) before `IdentityMismatch` is reported. That is a silent replacement
   identity and it pollutes the production Keychain from a dev profile.
   Fix: when `workspaces` is non-empty, call `keys.load()` only; map `NotFound` to a new
   `AppError::IdentityMissing` ("This workspace's device identity is missing; restore it or use the
   matching key store") — never create. Keep `load_or_create` only for the `Setup` case (no
   workspace). Regenerate the `AppError` binding and add the advice text. Tests: (a) mock store
   returning `NotFound` with an existing workspace → `IdentityMissing` and `create` never called
   (counting mock); (b) file-key profile whose identity file was removed → `IdentityMissing`, no new
   identity file written.
