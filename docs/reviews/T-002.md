## Matches the spec (accepted)
- ADR-010 exact bytes: genesis and events are signed over raw `genesis_bytes` /
  `postcard(header) || postcard(body)` with domain prefixes; `verify_strict`; signature checked
  before the body is decoded; trailing bytes rejected; nothing is re-encoded for dedupe.
- Receive order: decode envelope → verify → workspace check → dedupe/equivocation on raw signed
  bytes (first payload kept, author flagged) → field validation → contiguous/pending with
  transactional promotion. Invalid field events are never persisted.
- Workspace isolation, bounded queries (256 events / frame cap), bounded pending buffers with
  durable accounting over original envelope lengths.
- Identity: only `NotFound` permits generation; Locked/Unavailable/Invalid never replace a key;
  create-only Keychain insert (no keyring upsert race); file store with canonical parent,
  no-follow, 0600, fsynced staging inode + `hard_link` without overwrite. Secrets redacted and
  zeroized, never bound into SQL.
- Fold: owner seeded by genesis, owner membership first, ordinary events for all members
  including the owner, deterministic regardless of cross-author order.

## Required changes
1. **`Database::confirmed_author` is O(owner log) signature verifications per insert.**
   Every insert from a non-owner author re-reads, re-verifies (Ed25519) and re-validates the
   whole owner log; `current_epoch` (called on every own append) does the same plus a full fold.
   Owner logs will contain frequent `AgentState` events, so catch-up becomes quadratic and each
   live agent event costs a full log scan. Rows in `events` were already verified on insert;
   fix by maintaining a derived `members(workspace, device, epoch_added, removed)` table (or
   equivalent) updated **in the same transaction** that promotes contiguous owner
   `MemberAdded`/`MemberRemoved` events, and read `confirmed_author` / `current_epoch` from it.
   Keep the existing semantics (ever-confirmed authors keep their history). Add a regression
   test with ≥ 5 000 owner events that bounds the per-insert work (e.g. assert no full-log
   re-verification via a counting verifier, not a wall-clock threshold).
2. **`events_after` can return an empty page forever** if a single stored envelope is larger
   than `MAX_FRAME` (the check is on the outer envelope while insert bounds only `signed`). Either
   bound the outer envelope length at insert, or always return at least one event and let the
   frame layer handle it. Add a test. (T-006 cursor loop would otherwise stall.)
3. **Fold: `MemberRemoved` must not remove the genesis owner.** `MemberRemoved` is reserved for
   M2, but the fold currently drops the owner if the owner signs `MemberRemoved{owner}`. Ignore
   (and flag) that case; add a fold test.
