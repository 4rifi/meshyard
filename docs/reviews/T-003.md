## Required changes
1. **Relay suite: no home relay can be selected in the tested configuration.** The test runs Auto
   with `NetReportConfig::minimal()` (forced for every mode at `lib.rs:426`, `https_probes: false`),
   a local relay started with `run_relay_server_with(false)` (no QUIC), and IP transports cleared.
   In pinned iroh, `online()` waits for a connected home relay; with HTTPS probes off, no QUIC
   address discovery (no QUIC on the relay, no IP sockets) there is no relay measurement to choose
   one. Upstream's equivalent `endpoint_two_relay_only_no_ip` (endpoint.rs:2600) uses the default
   net-report config. This is the source-grounded explanation; it must be confirmed by the run.
   Fix (ADR-013 addendum): Auto builds with `NetReportConfig { https_probes: true,
   captive_portal_check: false }` (probes only the configured relay map); Strict unchanged. Keep the
   test's physical IP-transport absence, local relay and timeout; **do not** raise the timeout or
   label a direct path as relay. Acceptance: relay suite green **10/10** in a normal shell. If it
   still fails, stop and report the logs instead of tuning.
   (This is also a product issue: a self-hosted relay without QUIC would never become home relay in
   Auto with `minimal()`. T-R1 relays should enable QUIC regardless.)
2. **0-RTT not disabled (PROTOCOL §6 rule, ADR-013).** Pinned `iroh/src/tls.rs:89` sets client
   `enable_early_data = true`, `:125` server `max_early_data_size = u32::MAX`; no public switch.
   `max_tls_tickets(0)` only empties our client cache; awaiting the full handshake does not stop the
   server from accepting early data. Implement ADR-013 exactly: vendored unmodified 1.3.0 archive
   (checksum = `Cargo.lock`, licences, `PROVENANCE.md`), `vendor/iroh-1.3.0.patch` with only those two
   values (`false`, `0`), `[patch.crates-io]`, `exclude = ["vendor"]`, `.prettierignore`.
   Required tests:
   - (a) inside the patch, a `#[cfg(test)]` unit test in `tls.rs` asserting the built server config
     has `max_early_data_size == 0` and the client config `enable_early_data == false`; run once by
     explicit command (`cargo test --manifest-path vendor/iroh-1.3.0/Cargo.toml --offline tls::`) and
     recorded in the report (vendor is outside workspace test discovery);
   - (b) an independent rustls-level QUIC harness in `meshyard-net` tests (rustls `=0.23.46` is
     already in the graph; add it as an exact-pinned dev-dependency, no new crate): in-memory
     `rustls::quic` client with resumption + early data. **Positive control:** server config with
     `max_early_data_size = u32::MAX` → second handshake accepts 0-RTT (server reports early data
     accepted / 0-RTT keys present). **Patched value `0`** → early data rejected, and the 1-RTT
     handshake still completes. Assert rejection status, not "marker never seen" (rejected 0-RTT data
     may be resent after 1-RTT);
   - (c) existing endpoint suites still pass with the patched iroh (normal authenticated handshakes).
   A client that simply has no ticket does not count as server rejection.
3. **Keep T-005/T-006 mutating handlers closed** until findings 1–2 are reviewed (already the case:
   default handlers close without reading; keep it).
